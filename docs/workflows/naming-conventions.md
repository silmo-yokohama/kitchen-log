# 命名・重複防止ルール

## カテゴリー・素材・タグはマスタ照合（Step2で決定変更）

`categories`・`mainIngredients`・`tags` の値は `masters/taxonomy.json` を単一の情報源とし、スキーマ検証でマスタに無い値を弾く（選択式絞り込みで使うラベルの表記を統一するための許可値一覧。なお絞り込みパネルに表示されるのはマスタ全体ではなく、登録レシピで実際に使われている値のみ）。新しい値を使いたいときは、**先にマスタへ追加してから**レシピに書く。マスタへの追加時は既存値との表記ゆれ（例: 「韓国風」があるのに「韓国料理」を新設しない）に注意する。

> かつては「専用の辞書ファイルは作らない（Grepで十分）」としていたが、選択式絞り込みには許可値の一覧が必須のため、この3フィールドに限りマスタを持つ方針に変更した（`docs/superpowers/specs/2026-07-12-step2-viewer-design.md` 参照）。

## 食材名・dish・手順セクション名の表記ゆれ防止

新しい食材名（材料欄の`name`）・`dish`・`stepSections`のセクション名（下ごしらえ／調理／盛り付け等、固定enumではなく自由記述）を追加する前に、必ず `recipes/*.json` をGrepし、既存の表記があればそれを再利用する（例: `karaage` が既にあるのに `kara-age` を新設しない）。これらはマスタ化せず、従来通りGrepで防ぐ。

## `dish`・`categories`・`mainIngredients`・`tags` の使い分け

- `dish`: 同一の料理を束ねる識別子（例: `karaage`）。同じ`dish`を持つ複数のレシピ（例: クラシックな唐揚げ、スパイシー唐揚げ）が存在してよい
- `categories`: 料理の系統・形態（例: `["鍋料理", "韓国風"]`）。1つ以上必須
- `mainIngredients`: 主役級の素材（例: `["鶏肉", "豆腐"]`）。薬味・調味料は含めない。1つ以上必須
- `tags`: 上記に収まらない横断的な属性（例: `["時短", "さっぱり", "夏"]`）。0個でもよい

タグ等を既存レシピに遡及して付与したい場合は、マスタ照合→書き換え→commitの流れで行う。

## 新規レシピの作成手順

新しいレシピファイルは、必ず `docs/workflows/recipe-template.json` をコピーして作成すること。既存の別レシピファイルをコピーして作らない（`id`など、コピー元の値が誤って残るリスクがあるため）。テンプレートの`id`は`REPLACE_WITH_SLUG_MATCHING_FILENAME`という明らかなプレースホルダーになっており、ファイル名と一致するslugに必ず書き換える。

## id・ファイル名・`dish` のslug形式

`id`（＝ファイル名）と `dish` は、小文字ローマ字のケバブケースで書く（例: `enoki-butamaki`、`hiyashi-chuka`）。日本語・大文字・アンダースコアは使わない。`id` はファイル名（拡張子除く）と完全一致させる。

## スキーマにない単位に遭遇したとき

`unit` は固定enumであり、レシピ作成環境（クラウド）からはenumを拡張できない。enumにない単位（例: 「1房」「1切れ」）が必要になったら、その場でenum追加を試みず、次のように登録する。

- 可能なら `g`・`ml`・`個` 等の既存単位に換算する
- 元の表記が調理上重要な場合は `name` に併記する（例: `name: "ぶどう（1房分）", amount: 300, unit: "g"`）
- 頻出しそうな単位であれば、ローカル開発環境で `viewer/src/schemas/recipe.ts` の `UNIT_VALUES` に追加する作業を別途行う（ユーザーに提案する）
