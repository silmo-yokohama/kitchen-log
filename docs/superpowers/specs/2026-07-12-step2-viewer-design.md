# Step2設計: Astro製ビューア（一覧・詳細・絞り込み・人前スケーリング）

> 作成日: 2026-07-12
> 前提ドキュメント: `docs/superpowers/specs/2026-07-07-step0-foundation-design.md`（ロードマップ・技術スタック・NFR）
> ビジュアル仕様: `mockups/index.html`・`mockups/recipe-detail.html`（2026-07-11〜12にユーザーと合意済み）

## 背景・目的

Step2として、登録済みレシピをスマホで閲覧するビューアを実装する。Step0設計書のロードマップにある「Astro製PWAビューア（一覧・詳細・人前スケーリング・検索・タグ絞り込み）」に対応する。ただし検索は本設計セッションで**フリーワード検索ではなく選択式の絞り込み**（カテゴリー・素材・タグの3ファセット）に変更した（ユーザー決定）。

デザインは「北欧、暮らしの道具店」のdesign-md（awesome-design-md-jp）を正式指定として採用済み。モックアップ2画面が事実上のビジュアル仕様書であり、本設計はそれをAstroに移植する構成・データ設計・振る舞いを定める。

## スコープ

- 一覧ページ（絞り込みパネル付き）・詳細ページの実装
- 人前スケーリング（1〜6人前、分量の丸めルール込み）
- 選択式絞り込み（カテゴリー・素材・タグ）とそのためのマスタ・スキーマ変更
- PWAマニフェスト（ホーム画面追加のみ。オフラインキャッシュは不要 — Step0設計書で明記済み）
- Cloudflare Pages + Cloudflare Access へのデプロイ（ダッシュボード操作はユーザーと共同）

スコープ外: 調理モード（Step3）、お気に入り・週間予定表・買い物リスト（v2、Supabase）、Service Worker。

## 画面・URL構成

| ルート | 内容 |
|--------|------|
| `/` | レシピ一覧。ヘッダー（kitchen-log／陽平のレシピ帳）・絞り込みパネル・レシピカード縦積み |
| `/recipes/<id>/` | レシピ詳細。モックアップの構成（リード文→元レシピリンク→材料→作り方→栄養→動画FAB）を踏襲 |

- 全ページ`getStaticPaths`による静的生成。コンテンツ更新はgit commit→再ビルド
- アプリの名乗りは「陽平のレシピ帳」（ヘッダー・フッター・`<title>`・マニフェスト共通）

## データ・マスタ設計

### masters/taxonomy.json（新設、リポジトリ直下）

絞り込みファセットの**許可値マスタ**。Claude Codeのみが更新するデータなのでこのリポジトリに置く（data-boundary.mdのルール通り）。

```json
{
  "categories": ["鍋料理", "韓国風", "副菜", "..."],
  "ingredients": ["鶏肉", "キムチ", "豆腐", "小松菜", "..."],
  "tags": ["うどん入り", "時短", "甘辛", "..."]
}
```

### スキーマ変更（viewer/src/schemas/recipe.ts）

- `categories: string[]`（1つ以上）を新設 — 料理の系統・形態（鍋料理・揚げ物・中華等）
- `mainIngredients: string[]`（1つ以上）を新設 — 主要素材。ユーザー決定により**手動で明示的に持たせる**（材料名からの自動判定はしない）。薬味等は含めず主役級のみ
- `tags: string[]` は属性系（さっぱり・時短・季節等）専用に意味を狭める（0個以上）
- 3フィールドとも、値が `masters/taxonomy.json` に存在することをスキーマで検証する（スキーマがマスタをimportして照合）。値の表記ゆれを構造的に防ぐ

### 既存レシピの再分類（バックフィル）

| レシピ | categories | mainIngredients | tags |
|--------|-----------|-----------------|------|
| kimchi-chige-chicken | 鍋料理・韓国風 | 鶏肉・キムチ・豆腐 | うどん入り |
| sasami-komatsuna-amakara-itame | 副菜 | 鶏肉・小松菜 | 時短・甘辛 |

### ワークフロー文書の更新

- `naming-conventions.md`: 「専用の辞書ファイルは作らない（Grepで十分）」の決定を上書きし、categories/mainIngredients/tagsはマスタ参照に変更。新しい値を使うときは先にマスタへ追加する手順を明記。食材名（材料欄の`name`）・`dish`・手順セクション名は従来通りGrepで表記ゆれ防止（マスタ化しない）
- `authoring-workflow.md`: 登録の流れに「カテゴリー・素材・タグをマスタと照合し、必要ならマスタに追加する」ステップを追加
- `recipe-template.json`: 新フィールドを反映

## 絞り込みの挙動

- 一覧上部の絞り込みパネルに、カテゴリー・素材・タグの3ファセットをチップ（選択式）で表示。フリーワード入力は置かない
- パネルに出すのは**登録レシピで実際に使われている値のみ**（マスタにあるが未使用の値は出さない）
- 判定: 同一ファセット内はOR、ファセット間はAND
- 選択状態はURLクエリ（例: `/?ingredients=鶏肉&categories=鍋料理`）に反映し、ブラウザバック・リロード・共有に耐える
- 実装: 全カードを静的HTMLで出力し、カードの`data-categories`/`data-ingredients`/`data-tags`属性と選択状態を照合して`hidden`を切り替える小さなvanilla JS。0件時は「見つかりません」メッセージ

## 人前スケーリング

- 詳細ページに人前セレクタ（1〜6人前、初期値は`servings`）。登録値以外を選ぶと材料表・手順文中の分量表示が連動して書き換わる
- 分量はマークアップ時に`<span data-amount data-unit>`でマークし、JSが表示文字列を再計算する
- 丸めルール（`src/lib/scale.ts`の純粋関数、ユニットテスト対象）:
  - 大さじ・小さじ・カップ: 1/4刻みに丸め、「大さじ1と1/2」「小さじ1/4」表記
  - g・ml: 整数に丸め、100以上は5刻み
  - 個数系（個・本・枚・束・片・玉・丁・パック・株・袋・缶・かけ・尾）: 1/2刻み
  - 少々・適量・ひとつまみ: そのまま
- 栄養価・レーダーは1人前あたりのため人前変更の影響を受けない（セレクタ付近に注記）

## 手順文のレンダリングルール（確定）

`{{id}}`参照の展開は`src/lib/render-steps.ts`の純粋関数で行う（ユニットテスト対象）。

- 初出: 材料名＋分量（例: 「鶏手羽元（骨抜き）300g」）。`<strong>`で強調
- 同一レシピ内での再掲: 材料名のみ（分量を繰り返さない）
- 分量表記: 0.5→「1/2」、1.5→「1と1/2」のような調理慣習表記
- 「（味を見て）」「（下味用）」等の役割書きが名前に含まれる材料が「適量・少々」の場合、手順文中では役割書きと単位を省略して名前だけにする（例: 「塩で調える」）。材料表では省略しない

## 栄養表示の基準定数（1食の目安）

厚生労働省「日本人の食事摂取基準（2025年版）」の成人（18〜64歳）男女平均の1日推奨量・目標量÷3を「1食の目安」として`src/lib/nutrition-reference.ts`に定数化する（ユーザー決定: 個人目標ではなく公的基準の成人平均を使う）。

| 項目 | 1食の目安 |
|------|-----------|
| エネルギー | 775 kcal |
| たんぱく質 | 19 g |
| 脂質 | 22 g |
| 炭水化物 | 111 g |
| 食塩相当量 | 2.3 g |
| 食物繊維 | 6.5 g |
| ビタミンA | 260 μgRAE |
| ビタミンC | 33 mg |
| カルシウム | 240 mg |
| 鉄 | 3.0 mg |

- タイルの判定: 目安の120%以上=「▲高め」（赤 #c93a3a）、80%以下=「▼低め」（青 #1a6fae）、その間=「標準」
- レーダー: 破線=目安（100%）、目盛りは5段階、166.7%（=目盛り最大）で頭打ち描画
- モックアップの仮基準値とは微差があるため、表示上の高め/低め・レーダー形状はモックと若干変わってよい

## コンポーネント構成

```
viewer/src/
├── layouts/Base.astro          # デザイントークン（CSS変数）・フォント・共通head・マニフェスト参照
├── pages/index.astro           # 一覧
├── pages/recipes/[id].astro    # 詳細
├── components/
│   ├── RecipeCard.astro
│   ├── FilterPanel.astro       # 絞り込みチップ＋vanilla JS
│   ├── ServingsSelector.astro  # 人前セレクタ＋vanilla JS
│   ├── IngredientSections.astro
│   ├── StepSections.astro      # フェーズ・使うもの再掲・ステップ番号・圏点
│   ├── NutritionPanel.astro    # タイル＋レーダーSVG（ビルド時にnutritionから座標計算）
│   ├── NutrientDialog.astro    # 栄養素説明の共通辞書＋dialog
│   └── VideoModal.astro        # 動画FAB＋dialog（pause/resume、YouTube URLのときのみ出力）
└── lib/
    ├── scale.ts                # 分量スケーリング・丸め・表記
    ├── render-steps.ts         # {{id}}展開・初出/再掲・役割書きの畳み
    ├── nutrition-reference.ts  # 1食の目安定数・高低判定・レーダー座標
    └── source-link.ts          # 出典URLのドメイン抽出・YouTube動画ID抽出
```

- 対話部分（絞り込み・人前・2種のdialog）はそれぞれ独立した小さな`<script>`とし、viewer/CLAUDE.mdの「対話機能は個別Island」方針に従う。UIフレームワークは導入しない
- デザイントークン・タイポグラフィ（数字セリフ混植・圏点・英字ラベル等）はモックアップのCSSをBase.astroと各コンポーネントへ移植する

## PWAマニフェスト

- `name`/`short_name`: 陽平のレシピ帳 / kitchen-log
- `display: standalone`、テーマカラーは背景白・アクセント`#fb5c5c`系
- アイコン: ロゴタイプ準拠のシンプルな図案（コーラルの丸＋白地）をPNGで生成（192/512px）
- Service Workerは実装しない

## デプロイ（Cloudflare Pages + Access）

- Cloudflare Pagesでリポジトリ連携、ビルド設定（root: `viewer`、`npm run build`、出力 `dist`）
- Cloudflare Accessで陽平さん＋パートナーのメールのみ許可（Step0設計書のセキュリティNFR）
- ダッシュボード操作（アカウント・ドメイン・Access設定）はユーザーと共同で行う。実装→ローカル確認→デプロイの順で最後の段階とする

## テスト・検証

- `src/lib/*` のユニットテスト（丸め・展開・高低判定・座標・ドメイン抽出）
- レシピ検証テストの拡張: categories/mainIngredients/tagsがマスタに存在すること
- `npx astro check`・`npm run build` が通ること
- devサーバー（`--host`）でスマホ実機確認: 一覧絞り込み・人前切替・動画モーダル・栄養ポップアップ

## 本設計で上書き・変更する過去の決定

| 過去の決定 | 変更 |
